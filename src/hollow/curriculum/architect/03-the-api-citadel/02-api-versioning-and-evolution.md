# API Versioning and Evolution

> **Why this matters for you:** Your RPC to API migration was an evolution problem; seniors change APIs without breaking clients.

## You should be able to
- Compare URL, header and media-type versioning
- Make backward-compatible changes and deprecate safely
- Use contract tests and schemas to stop breaking changes

## Exam questions
- Which API changes are breaking, and which are safe?
- How do you retire v1 when you cannot see all its clients?
- What did versioning look like in your RPC to API migration, and what would you change?
