# CQRS and Event Sourcing

> **Why this matters for you:** This game is event-sourced: you can explain the pattern from your own code.

## You should be able to
- Explain CQRS and event sourcing, and that they are separate choices
- Handle projections, replays and schema changes of events
- Know when they are not worth it

## Exam questions
- Why does this game store events instead of current state?
- How do you change a rule that past events already replayed through?
- When is CQRS overkill?
